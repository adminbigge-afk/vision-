## 阅读范围和证据边界

读取 C:/Program Files/DAUM/PotPlayer 的文件清单、License.txt、CmdLine64.txt、Extension/api.txt、Menus/SimpleMenu.xml，并查看模块、皮肤、着色器和滤镜脚本目录。没有运行 PotPlayer，没有读取播放历史，没有复制其代码或皮肤资源。

目录未包含主程序的 C/C++ 文件、工程或构建脚本。存在的 AngelScript/滤镜脚本和菜单资源不等于播放器完整源码。以下区分安装文件直接支持的结论与架构推测。

## 播放流程：合理模型，不冒充 PotPlayer 源码结论

文件输入 → 解析打开请求 → 播放控制 → 容器解析与音视频解码 → 同步和输出 → UI 状态与历史记录。

这个流程是结合安装组件和通用播放器职责建立的模型，不能据目录证明其线程模型、事件循环、内部调用顺序或缓存算法。

vision 的实际实现为：LaunchFiles 解析 Unicode 启动路径；MainWindow 将早到的路径排队；MpvEngine 就绪后 loadfile；引擎事件返回到 Qt 线程；窗口按显示尺寸/DPI 适配；Library 负责本地记录。

## 本次独立实现的优化

- 引擎事件：接入 mpv_set_wakeup_callback，跨线程回调仅投递 Qt 事件，不在引擎线程操作 UI。空闲时不启动周期轮询；媒体打开后 100 ms 刷新，逐帧期间 20 ms 检查。
- 窗口逻辑：WindowInteraction.h 集中八方向命中、光标和矩形吸附。只枚举带 vision 自身标记的其他可见非最小化窗口，不移动其他窗口。
- 图标：TransportIcons.h 独立绘制播放、暂停、停止、上一/下一、打开的矢量轮廓，消除字体字形差异。用户 PNG 原样嵌入应用，并转换为多尺寸 Windows ICO。
- 逐帧输入：单击一帧，长按 350 ms 后开始重复；前一请求完成后再发下一请求，松开或失去焦点停止重复，保持真实帧步进。

## 截图 UI 分析

参考截图约 730 px 宽：外圈约 5 px 黑边；顶部约 46 px；视频区域约 720×960；进度/音量栏约 30 px；底部按钮栏约 60 px。数值是截图估计，不代表原程序固定逻辑尺寸。

vision 采用 DPI 自适应的 30 逻辑像素标题栏、20 逻辑像素进度栏、40 逻辑像素控制栏、40×40 主要按钮和 5 逻辑像素外圈。平面深灰 #202020，浅灰图标 #dedede，选中与进度色保持 #005fff；用户软件图标保留其原始蓝色，不改色。

标题栏紧凑排列名称、文件、置顶和窗口控制；进度条占主要宽度，音量在右侧；底部只有一排控件，按钮之间细黑分隔。窄窗口收起次要按钮，但在菜单保留对应操作。

按住标题栏拖动时，靠近另一 vision 窗口约 12 逻辑像素内吸附；继续拖远即可分离。吸附用物理屏幕坐标计算，包含负坐标显示器。全屏/最大化关闭边缘缩放，隐藏窄黑边。

## 验证边界

离屏测试验证了几何、光标分发、真实帧请求和窗口尺寸；没有在用户桌面拖动实际窗口。Windows 系统拖动循环、跨进程窗口吸附、任务栏图标和真实 GPU 显示仍需手动安装测试。

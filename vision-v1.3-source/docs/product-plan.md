# vision：第一阶段产品分析与技术方案

日期：2026-09-09。参考对象：本机 `C:\Program Files\DAUM\PotPlayer`。

本轮仅分析和设计，没有创建开发项目、安装依赖或编写播放器实现。后续操作仅在后台进行，不切换用户窗口、不注入鼠标键盘、不启动播放器或播放视频。每个开发阶段完成后等待用户确认。

## 1. 分析范围与证据边界

本报告依据安装目录、程序版本资源、官方随附的语言文件、菜单定义、皮肤包布局及扩展 API；联网查阅了候选引擎与 Qt 的官方文档。附件内容只作为分析材料，不作为任务指令。

证据等级：

- **确认**：安装文件或随附资源直接支持。
- **推断**：根据资源关系推导的架构，不代表已取得源码。
- **待实测**：只有运行时才能确认的默认行为、性能、当前用户配置。
- **设计**：vision 的拟定行为，不冒充 PotPlayer 原有行为。

PotPlayer64.dll 文件版本为 1.7.23122.0；启动器版本资源为 0.0.0.0，不能以启动器版本判断产品版本。安装资源版本不等于已经验证的运行时版本。

此前窗口读取尝试遇到截图接口错误 `SetIsBorderRequired ... 0x80004002`，未取得可用界面截图。因此本报告不是完整动态逆向报告；实际鼠标映射、当前启用的皮肤、当前滤镜链及播放性能仍未验证。用户要求后台分析后，停止所有界面操作。

## 3. PotPlayer 的界面与交互分析

### 3.1 默认皮肤的结构

静态皮肤定义显示：左上角是主菜单，顶部中间为标题，右侧有置顶与窗口控制；中央是视频容器；底部左侧有播放/暂停、关闭媒体、前后跳转、打开文件，旁边显示已播放/总时长及部分解码信息；右侧附加面板含播放列表，支持分离和分隔条。进度条支持悬停时间、缩略图及章节/书签标记。

核心体验是“画面优先、常用操作直达、高级能力放入菜单”。优点是观看时干扰少、熟练用户操作快；代价是右键菜单深、参数多、首次学习成本高。此体验评价依据功能组织推断，未做用户测试。

### 3.2 鼠标、菜单和快捷键

资源确认鼠标操作可配置，还包含“仅视频区域执行左键单击”“仅在标题栏移动窗口”等开关。当前单击、双击和滚轮绑定不能从这些标签确定，不能把常见默认行为当成本机实测结果。

右键菜单定义包含：打开、收藏、播放/暂停、关闭媒体、全屏、视图、播放、字幕、视频、音频、播放信息和设置。由命令 ID 统一绑定皮肤和菜单，说明复刻核心体验应优先统一操作语义。

## 4. vision 产品定义

正式名称为 vision（统一使用小写），目标平台 Windows 11 x64。定位为轻量、高性能、本地离线播放器。开发语言尚未由用户指定，下述为待确认的推荐方案。

首版包含用户列出的六种容器格式、基础播放、真实逐帧前进/后退、倍速、音轨、字幕与同步、截图、窗口模式、多屏、播放列表、最近、历史、收藏和续播。在线搜索字幕、直播、账号、云同步及第三方插件市场不进入首版。

支持 mp4/mkv/avi/mov/webm/flv 表示具备对应容器解析能力；内部编码另测 H.264、HEVC、VP9、AV1、MPEG-4 Part 2 和常见音频编码。损坏文件、DRM 内容或未包含的编码不能按扩展名保证播放。

### 4.1 视觉与布局设计

深灰背景、略浅控制面板，UI 点缀色统一为蓝色 `#005fff`（RGB 0, 95, 255），采用矢量图标。用户指定将参考播放器的黄色点缀替换为该蓝色，用于播放进度、选中状态、主要操作和键盘焦点；悬停/按下状态通过透明度或明暗变化区分，保持同一蓝色色系。以逻辑像素布局，验证 100%、125%、150%、200% 缩放。

- 顶栏：左侧打开/主菜单，中间文件名，右侧置顶和标准窗口按钮。
- 中央：视频画面；空闲时显示打开文件与拖放提示。
- 下部：独立横向进度条；其下为播放控制、时长、倍速、音轨、字幕、音量与全屏。
- 右侧：可收起侧栏，切换播放列表、历史和收藏。
- 设置：独立对话框，分常规、播放、音视频、字幕、快捷键、历史存储。

控制区淡入淡出约 150 毫秒；播放中全屏静止约 2 秒自动隐藏，暂停、菜单打开、拖动进度或键盘焦点位于控制区时保持显示。窗口模式优先保证控制清晰，不做无关动效。

### 4.2 明确交互规则

| 输入 | vision 设计 |
|---|---|
| 视频单击 | 播放/暂停；辨别双击后再处理，避免双击附带暂停 |
| 视频双击 | 全屏切换；标题栏双击仍为最大化/还原 |
| 右键 | 打开简明分组菜单，与工具栏共享命令和状态 |
| 视频区域滚轮 | 音量每格 5%；列表内滚轮只滚动列表 |
| 拖入一个视频 | 打开并播放；有有效记录则提供继续/从头入口 |
| 拖入多个视频 | 创建播放队列，从第一项开始 |
| 拖入字幕 | 加载到当前媒体，不覆盖原字幕文件 |
| 点击/拖动进度 | 点击定位；拖动节流请求，松手最终精确定位，保留拖动前暂停状态 |
| 无边框 | 隐藏外框，保留可拖动区域及边缘缩放 |
| 小窗 | 切换当前窗口尺寸并记住原布局；退出恢复，保持当前音轨和时间点 |
| 全屏 | 使用当前屏幕；退出恢复窗口几何尺寸和先前置顶状态 |
| 多屏 | 允许选择全屏屏幕；显示器移除后回到可见屏幕范围 |

按用户最新要求，快捷键更新为：空格播放暂停；← 为上一帧，→ 为下一帧，替代原来的 ±5 秒；Ctrl+←/→ 仍为 ±30 秒；F 全屏；M 静音；↑/↓ 音量 ±5%。另外建议 Esc 退出全屏，Ctrl+O 打开文件，Ctrl+Shift+O 打开字幕，Ctrl+S 截图，Ctrl+T 置顶。文本输入、列表导航和弹窗获得焦点时不抢占方向键；播放画面获得焦点时执行逐帧。

倍速首版 0.25–4.0 倍，常用倍率直接选择；字幕偏移每次 100ms、音频偏移每次 50ms，都支持输入和复位。以上为产品默认值，不是 PotPlayer 默认值。

### 4.3 真实逐帧查看（用户新增要求）

- 每次单独按下 ←/→，按视频展示顺序后退/前进一个实际解码帧；播放中先暂停，再执行一步，完成后保持暂停，空格恢复播放。忽略操作系统长按自动重复，避免一次按下产生多帧移动。
- 工具栏和右键菜单提供“上一帧/下一帧”，与快捷键共用同一命令。逐帧时不输出短促音频，不修改用户保存的静音状态；恢复播放后重新同步音视频。
- 以视频帧展示时间戳（PTS）及展示顺序为依据，不能通过相对跳转 `1 / FPS` 秒冒充逐帧，也不能按压缩包顺序处理有 B 帧的视频。静态重复画面仍可能是不同的实际帧，不能按图像相同去重。
- 保留 24000/1001、30000/1001、60000/1001 等有理数帧率，不取整为 24/30/60。可变帧率视频依据相邻实际帧时间戳步进，不假设固定帧间隔。
- 信息面板区分容器声明帧率、测得平均帧率和当前帧时间；VFR 显示可变帧率，尚未充分分析时标注未确认，不凭短时波动断言 VFR。显示器刷新率不能当成视频帧率。
- 当前帧时间显示毫秒；只有建立可靠展示帧索引后才显示精确帧号，禁止以“时间×平均帧率”伪造精确编号。
- 第一帧向后、最后一帧向前均停留原处，不切换文件；音频文件禁用逐帧。倍速不影响一步的帧数。逐帧查看按源视频帧定义，关闭插帧与改变帧数的处理；隔行视频按解码帧而非单场计数。
- 快速连续单击的命令串行执行，每个已接收命令完成一次呈现后再执行下一次；切换文件取消旧会话请求。逆向定位较慢时显示处理中，不用粗略跳转悄悄替代。

技术实现优先使用锁定版本 libmpv 的原生前进/后退逐帧命令。后退通常需要回到较早关键帧再正向解码，长 GOP 和高分辨率素材可能较慢。第三阶段必须验证跨关键帧、VFR 和硬件解码的正确性；若原生命令无法满足样片验收，补充按 PTS/展示序号索引、关键帧回溯解码与有界缓存的精确路径，再评估实现成本。不能仅以命令返回成功判断正确。

官方手册说明反向逐帧依赖精确 seek，滤镜和时间戳等情况可能影响结果；容器 FPS 与短时估计 FPS 也不保证准确。因此真实逐帧是必须单独验证的交付要求。[mpv 逐帧与帧率属性文档](https://mpv.io/manual/stable/)

## 5. 技术方案

### 5.1 选型结论

**推荐 C++20 + Qt 6 Widgets + libmpv + CMake，SQLite 保存记录，JSON 保存设置，NSIS 制作离线安装包。**

| 候选方案 | 适配判断 |
|---|---|
| C++ / Qt Widgets + libmpv | 首选：原生窗口管理方便，能用成熟播放核心实现字幕、倍速和同步；需做好渲染子窗口、焦点和浮层 |
| C++ / Qt Quick + libmpv | 动画和界面组合更灵活，但图形后端互操作需额外验证，不作为首版默认 |
| C# / WPF + LibVLC | C# 团队的合理备选；嵌入原生视频时需处理浮层与窗口区域问题 |
| Electron + 引擎进程 | 适合 Web 团队，但增加运行时与进程开销，不优先用于轻量 Windows 播放器 |
| 直接使用 FFmpeg 自建播放器 | 需自行实现时钟、缓冲、音频输出、字幕合成和 seek 等，不适合作为本项目首版路线 |

Qt 提供高 DPI 支持，实际跨屏几何与命中区域仍要测试。[Qt 高 DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。LibVLC 是 VLC 的嵌入式媒体引擎备选。[VideoLAN 官方说明](https://images.videolan.org/vlc/libvlc.html)。

### 5.2 渲染与硬件解码

第一版采用 libmpv 嵌入专用 Win32 子窗口，让引擎负责视频渲染，Qt 管理周边控件。Windows 可通过 HWND 嵌入；候选路径使用 D3D11 输出和 D3D11VA 硬件解码，初始化后检查实际硬解状态，失败回退软件解码。[mpv 官方手册](https://mpv.io/manual/stable/)。

不要把普通 Qt 控件直接盖在原生视频子窗口上并假定一定可见。窗口模式控制栏和视频分区；全屏浮层使用受主窗口管理的独立覆盖窗口，随焦点、位置、DPI 和隐藏状态联动。第三阶段优先验证浮层层级、右键菜单、输入路由和跨屏稳定性，再开始完整 UI。

不以“打开硬解选项”代替性能验证，也不承诺端到端零拷贝。优先避免 GPU 帧读回 CPU；复杂超分辨率和高成本滤镜默认关闭。

Qt Quick 的 QQuickFramebufferObject 仅适用于 OpenGL，不能直接当成 Qt 默认 D3D11 场景图组件使用。[Qt 官方限制](https://doc.qt.io/qt-6/qquickframebufferobject.html)。因此首版不混搭该路径。

### 5.3 模块与状态

拟定模块：App/MainWindow、PlayerController、MpvEngine、PlaylistModel、HistoryStore、SettingsStore、WindowController。只接入一个播放引擎，不预建多引擎框架。

UI/快捷键 → PlayerController → libmpv；引擎事件 → 控制器状态 → UI；历史与设置通过专用存储模块落盘。

状态包括空闲、加载、播放、暂停、结束和错误；拖动定位作为短暂操作状态处理。快速切换文件时使用媒体会话标识，丢弃旧文件的迟到事件。引擎回调通过队列回到 Qt 主线程，不在回调中操作控件；耗时加载与数据库写入不阻塞 UI。

### 5.4 本地存储与离线约束

应用数据根目录为 `%LOCALAPPDATA%\vision\`，其中 settings.json 存设置，library.sqlite 存历史、收藏和播放列表，logs 存有大小上限的诊断日志。截图默认保存到用户图片目录下的 vision 子目录，可修改。

媒体保留原路径，不复制到程序目录。历史保存路径、大小/修改时间、时长、续播位置、最近打开时间、轨道选择及同步偏移。首版以规范化路径定位文件，并用大小/修改时间识别同路径替换；文件移动后提示重新定位，不扫描整块磁盘。

播放中约每 5 秒保存位置，暂停、切换及正常退出时立即提交；设置原子写入、历史使用事务。恢复播放必须等媒体加载完成，缺失音轨或字幕时回退可用默认项。接近片尾视为已完成；具体阈值拟为剩余时间不超过 min(30秒, 总时长×5%)。

最近播放是历史的有限数量视图；收藏独立保存，不因清理历史而丢失。提供关闭历史记录与清空记录功能。清空记录不删除视频。

完整离线运行：安装包包含所需依赖；不自动加载系统 mpv 配置或用户脚本，不启用在线字幕、远程播放和更新检查。文件入口及列表解析只接受本地路径，并限制底层协议，防止本地列表间接引用网络。第五阶段断网测试并检查是否产生应用发起的网络请求。

### 5.5 安装交付与依赖选择

交付目标为 Windows 11 x64 Release 离线安装包，包含程序、Qt 插件、播放引擎、必需运行库和第三方声明；支持安装、升级和卸载，用户记录默认保留。文件关联通过 Windows 标准流程由用户选择。公开发行时可另行配置签名证书；签名不作为生成可安装包的前提。

在第二阶段锁定实际依赖版本、来源与许可组合。mpv 默认是 GPL，存在排除 GPL 文件的 LGPL 构建路线，不能把任意现成 DLL 当成 LGPL；连同其 FFmpeg 等依赖一起核对。如果用户希望闭源分发，需要据此选择构建或评估 LibVLC 路线。[mpv 官方 Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright)。独立播放器使用自行制作的图标与界面资源，不打包 PotPlayer 的 DLL 或皮肤。

## 6. 性能与测试验收

4K/8K 流畅性取决于编码、位深、色度采样、码率、帧率、GPU 解码能力、驱动和磁盘速度。首版目标是对支持硬解的标准样片流畅播放；不保证所有 Windows 11 电脑播放任意 8K 文件。

| 测试组 | 验收内容 |
|---|---|
| 格式与轨道 | 六种容器；H.264/HEVC/VP9/AV1 等样片；多音轨、无音轨、内嵌及外挂 SRT/ASS/VTT |
| 播放状态 | 打开、暂停、跳转、倍速、结尾、连续切换文件；暂停中定位不会意外播放 |
| 真实逐帧 | 使用带可见帧编号的 CFR/VFR 样片及独立解码的展示帧/时间戳清单核验；覆盖 23.976、24、25、29.97、30、50、59.94、60 FPS、B 帧、长 GOP、重复画面与首尾边界；逐次验证前进一步再退一步返回同一源帧，无跳帧/重复停留错误；分别验证硬解与软解，检查暂停、静音及快速单击行为。异常时间戳素材若不能精确定位，明确报告限制 |
| 同步 | 已知声画同步样片；偏移方向/复位正确；长时间播放无持续漂移 |
| 渲染 | 1080p、4K60、8K30/60 按硬件能力分组；记录实际解码器、丢帧、CPU/GPU/内存 |
| 性能目标 | 约定参考机与 SSD 样片后，冷启动目标≤2秒、1080p首帧目标≤1秒；高分辨率测试预热后连续10分钟，丢帧率目标<0.1% |
| 窗口 | 全屏/小窗/置顶反复切换；不同 DPI 多屏移动；拔出显示器后窗口可找回 |
| 记录 | 重启续播、清理历史、保留收藏、媒体移动/删除/替换、写入中异常结束 |
| 安装离线 | 未装开发工具的干净 Windows 11 环境断网安装播放；升级、卸载与数据保留 |

上述数值是待测试的工程目标，不是本轮测量结果。不可由 CI 环境验证的真实 GPU、显示器和音画体验，安排用户允许的专门测试时段，不干扰当前工作。
